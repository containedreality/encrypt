# encrypt

this is a collection of tools inspired by [encrypt(1)](https://www.illumos.org/man/1/encrypt), [decrypt(1)](https://www.illumos.org/man/1/decrypt) and [digest(1)](https://www.illumos.org/man/1/digest) from illumos.

it's supposed to be similar to the original tools, but you should expect major incompatibilities and major differences.

## Differences

### digest

There are the new algorithms:
* [blake2s](https://pkg.go.dev/golang.org/x/crypto@v0.58.0/blake2s)
* [blake2b](https://pkg.go.dev/golang.org/x/crypto@v0.58.0/blake2b)
* [sha3-256](https://pkg.go.dev/crypto/sha3)
* [sha3-384](https://pkg.go.dev/crypto/sha3)
* [sha3-512](https://pkg.go.dev/crypto/sha3)

digest defaults to blake2s, rather than erroring out because an algorithm wasn't choosen.

### encrypt

encrypt uses argon2id rather than PBKDF2 when a password is choosen.

`aes` now uses a key size of 256 bits rather than 128 bits.

Block ciphers use CTR mode.

It should be expected that this tool is completely incompatible with the files generated by the [encrypt(1)](https://www.illumos.org/man/1/encrypt) from illumos.

The following algorithms have been added:
* [crdpa](https://github.com/containedreality/crdpa) (for my personal usage, don't use it for yourself, i make that decision knowing how stupid it is)
* [speck](https://github.com/containedreality/speck) (express caution)
* [chacha20](https://pkg.go.dev/golang.org/x/crypto@v0.58.0/chacha20)

All ciphers are used with 256 bit keys when with a password.

Because all the ciphers use 256 bit keys now with when a key is derived from a password, DES and 3DES have been removed. For I don't want to deal with changing the key length parameter in Argon2 for each cipher.

`-T` and `-K` is missing for I have no clue what they do.
